Техническое Задание (PRD): Minerva / Credit Hunter
1. Описание проекта и Бизнес-цели
Minerva / Credit Hunter — это операционная система на базе Telegram для кредитных специалистов малого и среднего бизнеса (SME).

Главная бизнес-цель: Дать специалистам («хантерам») удобный полевой инструмент для быстрого обслуживания клиентов, подбора продуктов, генерации коммерческих предложений (КП) и автоматического трекинга активности.
Проект не заменяет основную CRM (EspoCRM будет подключена позже), а работает как «операционная память» (CRM-lite) и система ежедневной дисциплины (To-Do).

2. Архитектура и Платформы
Система реализуется как единое приложение (Monorepo), где все компоненты работают в связке:

Telegram Mini App (TMA): Основной рабочий инструмент для хантеров и руководителей филиалов.

Web Admin App: Панель управления для головного офиса.

Telegram Bot: Точка входа, канал для уведомлений и доставки документов.

AI Engine: Внешние API для интеллектуальной обработки текста и (в будущем) изображений.

3. Ролевая модель и Безопасность
Доступ строго контролируется через привязку Telegram ID к учетной записи в БД.

Superadmin: Полный доступ ко всей системе.

Head Office Admin: Управление продуктами, базой знаний, пользователями и филиалами.

Editor: Управление контентом (база знаний, продукты).

Branch Head (Руководитель филиала): Видит только свой филиал — своих сотрудников, их активность, клиентов и аналитику филиала.

Hunter (Кредитный специалист): Доступ только к Mini App. Видит свои задачи, своих клиентов и базу знаний.

Правило безопасности: При увольнении сотрудника админ деактивирует его профиль. Доступ к Mini App блокируется мгновенно, данные клиентов остаются у филиала.

4. Telegram Mini App (Пользовательский путь)
4.1. Главный экран (Home / Dashboard)
Экран отвечает на вопрос: «Что мне делать сегодня?»

Daily To-Do (Автоматический трекинг): Система сама формирует задачи (например, «завершить опросник», «отправить PDF»). Действия засчитываются автоматически.

Мини-дашборд: Выполнение дневной нормы (звонки, встречи, выдачи).

Быстрые действия: Новый клиент, Мои клиенты, База знаний, Калькулятор.

4.2. Флоу работы с клиентом (CRM-lite)
Данные сохраняются навсегда.

Создание черновика: Система создает сессию (ID клиента, филиал, время).

Опросник (Need Assessment): Реализован на базе динамической логики (JSON-дерево вопросов). Ответ на вопрос A определяет появление вопроса B. Это гарантирует предсказуемость и комплаенс.

Рекомендация: Строгая фильтрация предлагает подходящие кредитные и некредитные продукты на основе ответов.

Сборка корзины (Basket) и Калькулятор: * Ручная корректировка продуктов специалистом.

Калькулятор с предзаполненными лимитами высчитывает график платежей.

Генерация КП (PDF) с ИИ: * Запрашивается финальное имя клиента.

Участие ИИ: На этом этапе подключенная языковая модель (например, DeepSeek или Gemini по API) берет сухие данные из корзины и генерирует персонализированный, продающий сопроводительный текст для КП.

Генерируется PDF. При изменении параметров клиентом создается новая версия файла.

5. Web Admin App (Панель управления)
Минималистичный интерфейс. Структура:

Dashboard: Сухие операционные метрики.

Clients: Таблица всех клиентов с фильтрами по филиалам и экспортом в Excel.

Products: Управление кредитными/некредитными продуктами.

Articles (База знаний): Создание инструкций с таргетингом видимости по филиалам.

Users / Access: Управление доступом через Telegram ID.

6. Технологический стек и Инфраструктура (Replit-only)
Архитектура развертывания (Monorepo на Replit Core):
Всё приложение собирается в одном рабочем пространстве Replit. Используется скрипт запуска (например, bash или Procfile), который одновременно поднимает фронтенд, бекенд и Telegram-бота.

Frontend (Mini App & Web Admin):

React + TypeScript + Vite (компилируется в статику и раздается через FastAPI, либо крутится на соседнем порту).

Zustand (управление состоянием).

Telegram WebApp SDK.

Backend & Bot:

FastAPI (Python) — ядро логики и API.

Aiogram 3 (Python) — бот работает как фоновая задача (background task) внутри FastAPI или через Webhooks на URL Replit.

SQLAlchemy + Alembic (ORM и миграции).

WeasyPrint/Jinja2 для рендеринга PDF.

Database:

Replit Postgres: Встроенная облачная база данных PostgreSQL. Настраивается в 1 клик и подключается к бекенду через автоматически выдаваемый DATABASE_URL.

AI Интеграция (External APIs):
Поскольку у Replit нет мощных графических процессоров (GPU) для локального запуска тяжелых нейросетей, вся работа с ИИ ведется через внешние API:

Текст (Генерация КП): Вызовы к API OpenAI, DeepSeek или Gemini.

Зрение (Распознавание документов - MVP+): Отправка фотографий через API (например, Gemini 2.5 Pro Vision) для извлечения данных без нагрузки на сервер Replit.

7. Модель Данных (Базовые сущности PostgreSQL)
users, roles, branches

clients, client_status_history, client_actions

questionnaire_rules, client_answers

products, product_categories

baskets, basket_items, pdf_versions

articles, article_visibility

daily_metrics

8. Границы MVP
Входит в MVP: Единый хостинг на Replit (фронт, бек, БД, бот), Telegram-авторизация, иерархия филиалов, умный To-Do, опросник на динамической логике, калькулятор, версионирование PDF, базовая интеграция ИИ для генерации сопроводительного текста КП, сохранение истории (CRM-lite), админ-панель.

Исключено из MVP (на будущее): Прямая интеграция с АБС банка, синхронизация с EspoCRM, полная ИИ-автоматизация подбора продуктов (без участия человека), перенос на собственные выделенные серверы.
